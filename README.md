# Methane First — Figure Reproduction Code

This repo is the code behind the figures and tables in *"Methane First"* (Das, Kar, Das —
submitted to Tackling Climate Change with Machine Learning @ NeurIPS 2026). Its only job is to
make every figure independently reproducible from a cold start: no cached numbers, no fitted
curves standing in for a real model run.

Every script here was run end-to-end in a clean environment on 2026-10-11 to confirm it still
works and still reproduces the paper's own reported numbers before this repo was pushed. The
exact printed output of that run is quoted throughout this README so anyone can check their own
run against it.

## The two-phase model, in one paragraph

The paper asks: given a real fleet of U.S. gas-turbine data centers and a fixed annual
mitigation budget, how should that budget be split every year between methane leak repair
(LDAR) and carbon capture (CCS) — and does the answer depend on whether you score outcomes with
a 20-year or 100-year Global Warming Potential (GWP20 vs. GWP100)? **Phase A** keeps the fleet
fixed at 69 facilities and treats LDAR as a one-time purchase. **Phase B** grows the fleet on a
real, dated schedule (69 → 350 facilities by 2035) and treats LDAR as a recurring cost that has
to keep being paid or the leak rate drifts back up. The central finding: Phase A shows no real
trade-off, but Phase B does — under GWP20 the best fixed policy is LDAR-first, under GWP100 it's
CCS-first, and that crossover only exists once LDAR is modeled honestly as a recurring cost.

### Two supplementary scripts that are NOT in the paper's figure list

Two other scripts live in `model/` from earlier work on this project. Neither one is `\cite`'d
or `\includegraphics`'d anywhere in `main.tex` — they're background verification material, not
part of the submitted draft, and the figure map above doesn't include them:

- **`slugulator_reproduction.py`** — a line-by-line port of the University of Chicago
  Slugulator tool, run independently to confirm that methane's sharp short-lived forcing spike
  versus CO2's small, slow-building plateau (peak CH4 ≈ 0.42 W/m², CO2 at year 100 ≈ 0.016
  W/m²) is a real result of standard physics, not something assumed going in. Useful as a sanity
  check on the paper's core 20-yr-vs-100-yr argument, but the paper itself doesn't carry a
  Slugulator figure or citation — the `uchicago2026slugulator` entry in `references.bib` is
  currently unused in `main.tex`. If you want this reasoning visible in the paper itself, it
  would need an explicit figure and `\cite{uchicago2026slugulator}` added; right now it's repo
  documentation only.
- **`figure2_pipeline_diagram.py`** — an earlier, more detailed stand-in for the pipeline
  diagram, covering the same four climate-model stages (Joos 2013 / Etminan 2016 / Millar 2017 &
  Smith 2018) the real model actually uses internally. The paper's real pipeline diagram
  (`fig:nt`, right panel) is a simpler TikZ box diagram drawn straight in `main.tex`: 74 EIP
  facilities → 69-facility fleet → per-facility baseline → Phase A/B mechanic → REINFORCE policy
  → metric-crossover recommendation. Those four citations ARE real and ARE used in the paper, just
  in body text (`main.tex` line 135) describing the climate layer, not in a standalone figure.

## How to run it yourself

```bash
pip install numpy pandas matplotlib scipy scikit-learn
cd model
```

Run these in order — later scripts depend on files the earlier ones save to `../results/` and
`../data/`:

```bash
python3 build_facility_emissions.py       # processes the real 74-facility EIP fleet down to
                                           # the 69 with usable data -- prints the exclusion count
python3 run_path_scenarios.py             # baseline/mitigation forcing trajectories + model-
                                           # derived GWP20/GWP100 constants
python3 stage3_pipeline.py                # Phase A: trains the RL policy, saves fixed baselines
python3 stage3_trajectory_figures.py      # Figure 3
python3 stage3_training_curve_figure.py   # Figure 4
python3 stage3_phaseA_gwp20_only.py       # Phase A single-metric re-plots
python3 stage3_v5_qsweep.py               # Phase B at Q=1.5%/3.1%, both metrics (trains 4 policies)
python3 stage3_phaseB_dual_metric.py      # Figure 6
python3 stage3_v5_real_leak_rates.py      # Phase B at Q=0% standalone (Appendix numbers)
python3 stage3_v5_phaseout.py             # gas phase-out robustness scenario -- run before the next line
python3 stage3_phaseout_dual_cumulative.py  # fig:phaseout-cum (combines the CSVs the line above saves)
python3 stage3_phaseB_training_curve_gwp20only.py  # fig:phaseB-train
python3 stage3_nt_simple_figure.py        # fig:nt (left panel)
```

Two more scripts exist but aren't part of the paper's own figure set (see "Two supplementary
scripts" above) — run them separately if you want the Slugulator cross-check or the alternate
pipeline-diagram illustration, not as part of rebuilding `main.tex`'s actual figures:

```bash
python3 slugulator_reproduction.py
python3 figure2_pipeline_diagram.py
```

The whole thing runs in well under a minute — these are small 2-layer numpy MLPs trained with a
REINFORCE-style policy gradient (Williams 1992), no GPU needed.

## Two things worth knowing before you run it

**`stage3_v5_{GWP20,GWP100}_*` files (no "Q" in the name) are Phase B at Q=0%, not Phase A.**
True Phase A output is `stage3_allocation_ratio_trajectories.png` /
`stage3_cumulative_avoided_trajectories.png` / `stage3_training_curves_vs_baselines.png`. This
mix-up happened once already during development — worth avoiding twice.

**`Q` (the leak-rate floor) only exists in Phase B.** Phase A has no floor parameter because
LDAR is modeled there as a one-time purchase, not a recurring cost that drifts back up — that
distinction is the entire point of the paper's framing, not an oversight.

**`figures/phaseout_dual_cumulative.png` needs two scripts run in order.** `stage3_v5_phaseout.py`
computes the real GWP20/GWP100 phase-out trajectories and saves them as CSVs; the small
`stage3_phaseout_dual_cumulative.py` (added to this repo, not in the original trimmed handoff)
just re-plots those two already-computed trajectories side by side, matching the two-panel
layout the paper actually uses. No new modeling happens in that second script.

**Bibliography has 8 unused entries.** `etminan2016radiative`, `uchicago2026slugulator`,
`ipcc2021ar6wg1`, `pierrehumbert2014gwp`, `epa2023scghg`, `fractracker2026datacenters`,
`ieefa2026gasstampede`, and `zhou2026saftripartite` are all in `references.bib` but never
`\cite`'d in `main.tex` — background reading kept from earlier drafts. `etminan2016radiative` is
worth citing explicitly at the point where the GWP20/GWP100 constants are introduced (line 158),
since `dcfair.py` really does use the Etminan 2016 forcing formulas internally; the rest can
just be deleted in a final cleanup pass.

## Why `slugulator_reproduction.py` exists

Figure 1 is built on the University of Chicago Slugulator climate tool
(https://climatemodels.uchicago.edu/slugulator/slugulator.html). Rather than citing it and
hand-drawing a curve to match, `slugulator_reproduction.py` is a line-by-line port of the
tool's own source (every constant tagged with the exact source line it came from), run cold
with the tool's own default inputs. It reproduces the ~0.42 W/m² methane peak and ~0.02 W/m²
CO2 plateau as a direct result of the physics — the ratio between them is never hard-coded
anywhere in the script. Read the docstring at the top of that file for the full explanation.

## Data source

`data/eip_74_facilities.csv` is derived from the Environmental Integrity Project's July 2026
report *"The Power Behind AI: How the Data Center Boom Is Fueling a New Wave of Gas-Fired Power
Plants."* `build_facility_emissions.py` processes this down from 74 listed facilities to the 69
with usable capacity and technology data (4 excluded for no reported capacity, 1 for a
withdrawn/inactive permit), and prints that exclusion accounting every time it runs.
